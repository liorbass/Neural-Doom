1. Selective State Space Model (SSM)

The neural execution core is powered by Mamba SSM layers that maintain a continuous recurrent state across the entire lifetime of the guest CPU:

  • Continuous Recurrent Memory: Instead of recomputing attention over past history, Mamba compresses the entire program's execution history (stack frames, heap pointers, player HP, ammo, game ticks) into a compact recurrent state vector $h_t \in \mathbb{R}^{D \times 16}$.
  • O(1) Constant Compute & VRAM: Memory usage never grows over time, allowing DOOM to run indefinitely without performance degradation or memory leaks.
  • Input-Dependent Selection: SSM parameters (&bar;B, C, Δ) are dynamically parameterized by the current input, allowing the model to selectively remember critical CPU registers and forget transient ALU flags.

2. Multi-Task Output Prediction Heads

A single neural forward pass predicts all execution side-effects simultaneously without autoregressive token generation:

  • Branch Condition Head: Outputs a single logit trained with Binary Cross-Entropy (BCE) predicting whether a conditional branch is TAKEN or FALLTHROUGH.
  • Target PC Head: Predicts 4-byte aligned relative branch offsets with 100% architectural alignment validity.
  • Register Write Bitmask: A 32-bit sigmoid output identifying exactly which general-purpose registers (x0 to x31) are modified by the block.
  • Memory Bus Store Detection: Identifies store instructions consuming memory bus write slots.

3. Feature Representation & Training Supervision

Bit-Level Program Counter (PC): The 32-bit guest PC is unpacked into 32 binary features [b0, ..., b31] to eliminate continuous address hallucination.
Log1p Register Normalization: Register values are normalized via ln(1 + R)/22.2, preserving exact representations for small integers, loop counters, and heap pointers.
Ground-Truth Supervised Training: Trained on millions of execution traces captured from native RV32I DOOM execution with full hardware register and memory ground truth.

Tier 1: In-Engine Embedded C/WASM Kernel

Rather than relying solely on external JS/ONNX runtime calls, Mamba-Nano's forward pass is implemented as a hand-vectorized C kernel directly inside rv32i.wasm:

  • Zero JS-to-WASM FFI Overhead: The neural kernel reads CPU registers and memory directly in WASM linear memory with zero pointer translation or serialization.
  • Zero GC Pauses: State vectors and buffers are pre-allocated in linear memory, completely eliminating JavaScript garbage collection spikes.
  • Ultra-Low Latency: Executes in ~15 µs per block, enabling over 70,000 neural block evaluations per second.

Tier 2: Dynamic Mega-Block Chaining

DOOM execution contains tight loops and deterministic ALU/load/store sequences:

  • 128-Instruction Chaining: Consecutive instructions within basic blocks and loop bodies are chained and executed in C up to 128 instructions per dispatch.
  • Branch Consultation: The engine halts at each block terminator to consult the neural head; the prediction is scored against ground truth and the interpreter retires the true target.
  • Dispatch Amortization: One ~15 µs neural consultation per 128 interpreted instructions; the neural observer path runs ~9 MIPS while the plain interpreter reaches ~126 MIPS in the same WASM module (DOOM needs ~0.6M instructions per 35 Hz tic).

Tier 3: Asynchronous Zero-Delay MessageChannel

Decouples the execution loop from the browser UI thread:

  • Zero-Delay Task Loop: Uses MessageChannel macro-tasks for continuous, uninterrupted neural stepping without timer clamping.
  • Synchronized Vsync Rendering: Canvas updates (ctx.putImageData) run directly inside requestAnimationFrame at 60 Hz, preventing compositor starvation and frame drops.

Speculative Branch Retirement Architecture

Modeled after modern speculative out-of-order CPU architectures:

  • Neural Prediction: The neural network predicts TAKEN vs FALLTHROUGH on every branch.
  • Verified Hardware Retirement: Ground-truth registers verify the decision before committing state, eliminating compounding arithmetic drift while recording true neural accuracy (~80-95%).

⚡ What is the ALU + Barrel Shifter in ARM?

In classical ARM (ARMv4T / ARM7TDMI), every arithmetic instruction (ADD, SUB, AND, ORR, etc.) passes its second operand (operand 2) through a dedicated 32-bit hardware barrel shifter before reaching the ALU input.

ARM32 Compound Operation (1 Instruction, 1 Cycle):
add r0, r1, r2, lsl #2
// r0 = r1 + (r2 << 2) [base + index * 4 in 1 cycle]
RISC-V (RV32I) Orthogonal Operation (2 Instructions):
slli t0, a2, 2
add a0, a1, t0
// Explicit shift followed by explicit addition

Why ARM did this: In 1985, memory bandwidth was extremely slow. Combining shifts with arithmetic increased code density and kept the single-issue pipeline fed without extra instruction fetches.

🎯 Predication & Global Status Register (CPSR)

ARM dedicates bits [31:28] of every 32-bit instruction to one of 16 condition codes (eq, ne, cs, cc, mi, pl, vs, vc, hi, ls, ge, lt, gt, le, al, nv).

ARM32 Branch-Free If-Else:
cmp r1, #0
addeq r0, r0, #1  // executes only if Z == 1
subne r0, r0, #1  // executes only if Z == 0
RISC-V (RV32I) Minimal Branching:
bne a1, zero, else_label
addi a0, a0, 1
j end_label

Why RISC-V dropped it: Predication wastes 4 bits in every opcode (25% of encoding space) and makes out-of-order execution, register renaming, and superscalar retirement far more expensive in hardware.
